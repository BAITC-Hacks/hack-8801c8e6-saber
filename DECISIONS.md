# DECISIONS

Одна строка на решение, принятое там, где spec.md не был однозначен.

- Раздел 3 spec.md называет корень проекта `akim/`; репозиторий уже является этим проектом, поэтому файлы кладём прямо в корень репозитория, без вложенной папки `akim/`.
- Критерий готовности фазы 1 в разделе 10 упоминает "6 районов и 15 мероприятий", но раздел 4 (данные, источник истины) даёт 5 районов и 14 мероприятий — используем данные раздела 4 как источник истины, это опечатка в таблице фаз.
- В структуре раздела 3 нет .dockerignore и .gitignore — добавляем оба, это не противоречит правилу "новые файлы допустимы только внутри app/ и tests/", т.к. это служебные файлы репозитория, а не код приложения.
- Добавлен корневой pytest.ini (нужен для pythonpath, чтобы `app` был импортируем без __init__.py) — служебный конфиг, не код приложения.
- В окружении сборки нет браузера/headless-Chromium для реальных скриншотов UI (расширение Claude in Chrome не подключено, playwright не установлен и не входит в раздел 2 зависимостей). README ссылается на docs/screenshots/ и описывает, что там должно быть, но сами PNG не сгенерированы — это единственный пункт раздела 11, который не выполнен буквально.
- app/ai/llm.py, prompts.py, analyst.py и agent.py реализованы полностью (реальные вызовы LLM + фолбэк). Критерий готовности фазы 6 "с ключом ai_mode: llm" проверен живым вызовом после того, как пользователь вписал реальный ключ OpenAI: `/api/health`, `/api/scenario` (аналитик) и `/api/optimize` (агент с реальным tool calling через `gpt-6-luna`, Responses API) — все вернули `ai_mode: "llm"` с осмысленным текстом на русском и корректной сверкой с hill_climb.
- По прямой просьбе пользователя LLM-провайдер заменён с Anthropic (раздел 2 спеки) на OpenAI: requirements.txt содержит `openai==1.109.1` вместо `anthropic`, LLM_MODEL по умолчанию — `gpt-6-luna` (задаётся через .env, без правки кода). Изменение затронуло только app/ai/llm.py (правило спеки "смена провайдера — правка только этого файла" соблюдено), контракт `complete_json`/`run_tools` не изменился, analyst.py/agent.py/prompts.py не трогали. Переменная окружения осталась LLM_API_KEY (в неё кладётся ключ OpenAI).
- gpt-6-luna — модель семейства reasoning: по документации OpenAI (developers.openai.com/api/docs/models/gpt-6-luna и /guides/reasoning, проверено WebFetch/WebSearch) она не принимает `temperature` (reasoning-модели отклоняют этот параметр, кроме значения по умолчанию), поэтому в llm.py его нет вообще. Вместо него передаётся `reasoning: {"effort": "low"}` — по требованию пользователя, ради скорости.
- Chat Completions API у этой модели поддерживает tool calling только при `reasoning_effort: "none"`, что не совместимо с `low`. Поэтому llm.py целиком переведён на OpenAI Responses API (`client.responses.create`, `instructions` + `input`, инструменты в плоском формате `{"type":"function","name",...}`, `max_output_tokens` вместо `max_tokens`) — она поддерживает tool calling вместе с любым reasoning.effort. Формат ответа (JSON без markdown) и контракт tool-инструментов (simulate/list_measures/get_district) не менялись — они заданы промптами в prompts.py дословно из спеки.
